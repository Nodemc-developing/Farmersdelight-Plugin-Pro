# 手动内容包与煎锅支架修复验证

基线为 main 的 `3280b54f71ed86a0bd6de36d8ac93d1fdd7c4b96` 加既有 1.2.4 未提交工作区修复；交付为 1.2.5 本地候选。没有提交或上传。

## 根因与改动

1. 热源条目把省略的 `tray` 读为 `false`，覆盖支架的自动形状判断。改用可为空的布尔值，并拒绝拼写错误的布尔输入。
2. 仅停止启动复制不够：默认配方写入、JAR 资源层和特殊配方补齐仍可恢复被删除的内容。关闭这些自动入口，移除内部自动释放类，另行构建手动 ZIP；保留明确的附属 API 注册能力。
3. 手动包与 CE 内置配置存在内容相同的原生状态映射。按来源状态和目标状态的原生 ID 识别等价映射，允许合并；不放宽结果不同的冲突。
4. 支架增加交互、物理变化和区块加载处理后的刷新；更新按位置合并，世界操作沿用所属线程。

上游参考：[HuiDu_OwO 的 TrayManager](https://github.com/IOVEYOUMC0/Farmersdelight-Plugin/blob/main/src/main/java/com/huidu/farmersdelight/manager/TrayManager.java)。上游已有热源和非完整方块判断，本项目保留的同源代码已有该机制；此次修复的是新增配置覆盖及刷新缺口，无须复制另一套支架或模型实现。保留原作者归属及 AGPL、素材 MIT 许可。

## 限制及失败记录

- 无真实游戏客户端；未确认客户端的最终画面和交互手感。
- 区块项直接调用 FD 的加载处理器，检查已有 CE 区块中的过期支架状态；不是一次真实卸载、磁盘读回的全流程测试。
- 第一轮发现并修复了等价映射误冲突。第二轮测试夹具向全服重放 ChunkLoadEvent，触发 CE 自身重复装载；改为仅调用待验收的 FD 处理器后通过。未用这次夹具失败宣称生产环境发生区块数据故障。
- 未重跑所有 Minecraft 小版本、Folia 和其他插件组合，也未做性能跑分。此前报告保留为历史基线，不能当作本候选的全矩阵新实测。
